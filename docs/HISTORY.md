# 历史版本

白板保存时按间隔留下全量快照，替代早期的一次性 `.bak`。设计参考 VS Code Local History：按条数保留，不按天数过期。

## 存储位置

```
<工作区>/.superboard/history/<public|private>/<slug>/
  1764141234567-a1b2c3d4e5.canvas
```

- 文件名 = 毫秒时间戳（13 位）+ 内容哈希（10 位十六进制）。
- 内容是完整的白板 JSON，不做增量补丁；媒体文件仍在工作区 `assets/`，不在快照里。
- `.superboard` 以点开头，白板列表、文件夹列表、导出扫描都会跳过。

## 采样规则

- 默认每 5 分钟最多一份，可在设置 → 常规修改（0 = 关闭）。
- 只在该白板确实保存（自动保存防抖 1.2 秒）后判断，所以长时间不编辑不会产生快照。
- 内容与最新快照哈希相同则跳过；没有历史时第一次保存就留一份。
- 白板 JSON 超过 2MB 时跳过，避免大文件乘以条数。
- 每块白板默认保留 50 份，超出后删除最旧的；上限可在设置修改（内部硬上限 1000）。

## 恢复

- 恢复前先把当前内容写入历史，再替换为选中版本；因此恢复本身可以再撤销。
- 恢复只改白板文件，不动历史条目。
- 恢复后 `meta.updatedAt` 更新为当前时间。

## 生命周期

- 白板改名：历史目录跟随新 slug。
- 白板删除：历史目录一起删除。
- 文件夹删除：先扫描文件夹内的 `.canvas`，把对应 slug 的历史全部删除，再删目录。
- 设置页提供「清空全部历史」；白板历史弹窗提供「清空本白板历史」。
- 不做启动时静默扫描清理；孤立条目由用户显式清理。

## 接口

桌面（Go）与浏览器（File System Access）、开发服务器（Node）三套后端保持同一组路径：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/__canvases/:slug/history?scope=` | 列出条目与总大小 |
| GET | `/__canvases/:slug/history/:id?scope=` | 读取单条快照 |
| POST | `/__canvases/:slug/history/:id/restore?scope=&historyLimit=` | 恢复 |
| DELETE | `/__canvases/:slug/history?scope=` | 清空本白板 |
| GET | `/__history` | 全部历史占用与数量 |
| DELETE | `/__history` | 清空全部历史 |

写入白板时通过 `historyInterval`（秒）与 `historyLimit`（条数）两个查询参数传入当前设置。

## 迁移说明

旧版本在工作区留下 `<slug>.canvas.bak`。升级后不再写入，也不会自动删除；确认不需要后可以手动清理。
